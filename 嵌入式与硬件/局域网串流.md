# 局域网串流

> Sunshine + Moonlight + VDD 局域网串流与自动防窥完整手册

## 一、最终架构

^architecture

| 组件 | 作用 | 典型配置 |
|------|------|----------|
| **实体屏（LGD）** | 平时显示 Windows；串流期间被禁用 | 2560x1440, ~240 Hz, 主显示器 |
| **VDD by MTT** | 作为 Sunshine 专用串流显示器 | 固定 1920x1080, 60 Hz, SDR |
| **Sunshine** | 采集 VDD、硬件编码、管理显示器和音频 | Windows 服务后台运行 |
| **Moonlight** | 在 iPad/Android 解码画面、传回输入 | 同一局域网配对使用 |
| **路由器** | 承载局域网视频、音频和输入数据 | 客户端优先 5 GHz；主机优先网线 |

**最终效果：** 平时实体屏正常使用；Moonlight 连接后实体屏黑屏/无信号，客户端继续显示完整 Windows 桌面；退出会话后约数秒恢复实体屏。

## 二、安装流程总览

^install-overview

1. 安装并验证 Virtual Display Driver
2. 处理冲突设备（GameViewer 或重复 VDD 实例），只保留一个可用 VDD
3. 在 Windows 中将实体屏和 VDD 设置为"扩展这些显示器"
4. 安装 Sunshine Windows x64/MSI 版本，确认服务后台运行
5. 安装 Moonlight，在同一局域网配对，先测试普通 Desktop 串流
6. 从 Sunshine 日志中找到 VDD 的 `device_id`
7. 设置 `output_name`，只捕获 VDD，确认画面正常
8. 启用 `ensure_only_display`，固定 1080p60、关闭 HDR
9. 完成声音、码率和网络参数调整
10. 保存救援命令和维护注意事项

> 重要原则：**先跑通普通串流，再开启自动防窥。** 否则一旦显示器选错，实体屏可能黑掉，排错难度明显增加。

## 三、Virtual Display Driver 安装

### 安装方式

**方式一：WinGet**

```powershell
winget install --id=VirtualDrivers.Virtual-Display-Driver -e
```

**方式二：Virtual Driver Control (VDC)**

从官方 Releases 下载 VDC，解压后右键 `VDC.exe` 以管理员身份运行，点击 Install。

### 验证安装

WinGet 显示已安装并不代表 PnP 驱动设备已成功注册。必须检查：

```powershell
# 确认 VDD 设备出现在 Display 类中
Get-PnpDevice -Class Display | Format-Table Status,FriendlyName,InstanceId -Auto
```

成功安装后应看到类似：
- `Virtual Display Driver` / `IddSampleDriver Device HDR`
- `Intel UHD Graphics`
- `NVIDIA RTX 4060`

### 清理冲突设备

^cleanup-conflicts

如果同时存在 GameViewer、两个 VDD 实例等，Windows 无法稳定保存扩展显示拓扑。
**注意：如果禁用GameViewer后，检查发现GameViewer重新启动，可能是有其他远程串流软件的干扰（例如UU远程），此时要关掉多余的串流软件，重新使用以下命令禁用。**

```powershell
# 禁用冲突设备（InstanceId 以本机查询为准）
Disable-PnpDevice -InstanceId 'ROOT\DISPLAY\0000' -Confirm:$false
Disable-PnpDevice -InstanceId 'ROOT\DISPLAY\0002' -Confirm:$false

# 验证
Get-PnpDevice -Class Display | Format-Table Status,FriendlyName,InstanceId -Auto
```

### Windows 显示器设置

安装后务必设置为"扩展这些显示器"，而不是复制模式。如果遇到"这些显示设置与你的硬件配置不匹配"的提示，优先检查是否有冲突设备。

## 四、Sunshine 安装与配置

### 安装

1. 从 Sunshine 官方 Release 下载 Windows x64/AMD64 MSI Installer
2. Intel 处理器同样选择 AMD64/x64
3. 安装后重启 Windows

### 访问 Web UI

```
https://localhost:47990
```

自签名证书提示可继续访问。首次打开时创建管理用户名和密码。

### 服务管理

MSI 安装版作为 Windows 服务后台运行，日常不需要手动双击 `sunshine.exe`。

`Win + R` → `services.msc` → 确认 Sunshine 服务状态为"正在运行"，启动类型为"自动"。

> 规范排错：关闭黑色控制台窗口后，只要 `https://localhost:47990` 仍能打开，说明后台 Sunshine 服务仍在运行。不要同时运行第二个实例。

### 配对 Moonlight

1. 电脑和 iPad/Android 连接同一路由器
2. 打开 Moonlight，点击自动发现的电脑；未发现时手动输入电脑局域网IP
3. Moonlight 显示四位 PIN 后，在 Sunshine Web UI 的 PIN 页面输入
4. 配对成功后，先点击 Desktop 测试——确认画面、鼠标、键盘、声音都正常（此时实体屏仍亮是正常的）

## 五、识别 VDD 与自动防窥配置

### 从 Sunshine 日志识别 VDD

在 Web UI 的 Troubleshooting 中查找 `Currently available display devices`。日志中会显示类似：

```
VDD by MTT
  device_id   = {5eb52002-659f-5729-bdd8-9cdc4efd1bf5}
  display_name = \.\DISPLAY36
  resolution   = 800x600
  refresh_rate = 60 Hz

实体 LGD 屏
  device_id   = {99b63118-c5c6-5bf3-967e-4e04c199d03d}
  display_name = \.\DISPLAY1
  resolution   = 2560x1440
  primary      = true
```

> Windows 下 `output_name` 必须填 `device_id`（GUID 格式），不能简单填 `DISPLAY2`。

### 编辑配置文件

如果 Web UI 配置项控件未正常渲染（搜得到但点不了），直接编辑配置文件：

以管理员身份打开：

```
notepad "C:\Program Files\Sunshine\config\sunshine.conf"
```

### 最终稳定配置

^final-config

```
output_name = {5eb52002-659f-5729-bdd8-9cdc4efd1bf5}

# 第一轮只加 output_name，测试正常后再加以下配置

output_name = {5eb52002-659f-5729-bdd8-9cdc4efd1bf5}
dd_configuration_option = ensure_only_display
dd_config_revert_on_disconnect = disabled
dd_config_revert_delay = 3000

dd_resolution_option = manual
dd_manual_resolution = 1920x1080
dd_refresh_rate_option = manual
dd_manual_refresh_rate = 60
dd_hdr_option = disabled

stream_audio = enabled
```

各参数说明：

| 参数 | 作用 | 原因 |
|------|------|------|
| `output_name` | 固定捕获 VDD | 防止默认捕获实体屏 |
| `ensure_only_display` | 连接时启用VDD、禁用其他屏 | 实现实体屏熄灭 |
| `revert_on_disconnect = disabled` | 不因客户端短暂断连立刻恢复 | Android 连接初始化时可能重连 |
| `manual 1920x1080/60` | 固定VDD模式 | 消除客户端分辨率/FPS差异 |
| `dd_hdr_option = disabled` | 保持SDR | 排除HDR兼容性问题 |
| `stream_audio = enabled` | 发送系统声音 | 客户端播放游戏音频 |

## 六、自动防窥测试流程

^privacy-test

1. 重启 Sunshine 服务
2. 确认 Windows 当前仍为"扩展这些显示器"，VDD 可在系统中枚举
3. Moonlight 使用 1080p60、HDR 关闭
4. 点击 Desktop：实体屏应短暂切换后保持黑屏，客户端继续显示桌面
5. 保持连接 1 分钟，确认实体屏不会重新亮
6. 在 Moonlight 中选择 Quit Session，等待约 3 秒，确认实体屏恢复

> 正确结束会话：由于 `revert_on_disconnect` 设为 disabled，应在 Moonlight 中使用 Quit Session 而不是仅划掉 App。

## 七、客户端参数配置

### iPad 与 Android 建议参数

| 设置项 | iPad 建议 | Android 建议 | 说明 |
|--------|-----------|-------------|------|
| 分辨率 | 1920x1080 | 1920x1080 | 统一参数，避免主机显示模式反复切换 |
| 帧率 | 60 FPS | 60 FPS | 稳定后再单独测试 90/120 FPS |
| 码率 | 20-30 Mbps | 15-20 Mbps 起步 | Android 从低码率逐步提高 |
| 编码 | HEVC 或自动 | HEVC 或自动 | 兼容性异常时可临时测试 H.264 |
| HDR | 关闭 | 关闭 | VDD 稳定基线使用 SDR |
| 音频 | Stereo | Stereo | 手机和平板无需 5.1/7.1 |

### 升级顺序

先稳定 1080p60，再依次试 1080p90、1080p120 或 1440p60。一次只改一个变量；出现黑屏恢复、连接过慢或杂音时立即退回上一档。

## 八、声音设置

### 基础配置

Sunshine 日志确认音频链路正常：48 kHz、双声道、Opus 低延迟编码。通常只需保持 `stream_audio = enabled`，Moonlight 选择 Stereo。

`audio_sink` 留空：Sunshine 采集 Windows 默认输出设备。

### 主机静音（可选）

如果想让客户端出声而电脑扬声器静音：

```
install_steam_audio_drivers = enabled
virtual_sink = Steam Streaming Speakers
```

查询 Windows 音频设备：

```powershell
& "$env:ProgramFiles\Sunshine\tools\audio-info.exe"
```

### Android 杂音处理

如果 iPad 正常但 Android 有"滋滋声/爆音"（同一主机、同一 Sunshine）：

1. Android 降到 1080p60、10-15 Mbps、Stereo、HDR 关闭
2. 关闭蓝牙，用手机扬声器测试；若杂音消失，问题在蓝牙链路或 2.4 GHz 干扰
3. 确认手机连接 5 GHz Wi-Fi，尽量靠近路由器
4. 关闭手机空间音频、音质增强、低音增强等效果
5. 在 Moonlight 打开性能统计，观察网络丢帧是否在杂音出现时上升
6. 逐步提高码率到 15、20、25 Mbps，找到无杂音的最高稳定档

## 九、连接优化与故障排查

### 网络拓扑优先级

| 主机连接 | 客户端连接 | 评价 |
|----------|-----------|------|
| 电脑网线 | 5 GHz Wi-Fi / Wi-Fi 6 | 最佳，最推荐 |
| 电脑 5 GHz Wi-Fi | 5 GHz Wi-Fi | 可用，但无线链路传输两次，更容易抖动 |
| 电脑或客户端 2.4 GHz | 任意 | 不推荐，易丢包、爆音 |
| VPN/WARP/代理接管局域网 | 任意 | 可能改变路由或阻断发现，应先关闭排查 |

### Moonlight 性能统计

- **Frames dropped by network connection**：应长期接近 0%。升高说明丢包或码率超过链路能力
- **Frames dropped due to network jitter**：表示数据到达时间不均匀，常见于 Wi-Fi 干扰
- **Decode latency**：网络丢帧接近 0 但解码延迟很高时，降低分辨率/帧率或改编码器
- **Network latency**：频繁大幅跳动说明链路抖动，不是单纯平均网速不足

### 常见故障速查

| 现象 | 处理 |
|------|------|
| WinGet 有记录但没有第二块屏 | 用 VDC 以管理员运行 Install/Repair；重启后重新查询 |
| "复制 1 和 3"无法改成扩展 | 存在多个虚拟适配器冲突，禁用多余设备 |
| Sunshine 配置点不了 | 直接编辑 `sunshine.conf` |
| 串流时实体屏黑一下又亮 | 固定主机 1080p60、关闭 HDR、`revert_on_disconnect=disabled` |
| iPad 能熄屏 Android 不能 | 固定主机显示模式并降低 Android 码率 |
| 退出后实体屏没恢复 | Quit Session（不要划掉App）；Win+P 切"扩展"临时救援 |
| Sunshine 找不到显示器 | Win+P → 扩展；确认 VDD；重启 Sunshine 服务 |
| Sunshine 报 `terminate called recursively` | 服务已运行又手动双击了 sunshine.exe，关闭手动窗口 |

### 窗口救援快捷键

^window-rescue

| 场景 | 快捷方式 |
|------|----------|
| 窗口在屏幕外 | `Alt+Space` → X（最大化）；或 `Win+Shift+左/右` 移回 |
| 显示模式混乱 | `Win+P` → 扩展 |
| 实体屏一直黑 | `Win+P` 切换模式；必要时安全模式卸载 VDD |
| Web UI 打不开 | `services.msc` 检查 Sunshine 服务；避免双实例 |

## 十、日常维护

### 每次使用流程

^daily-use

1. 开机后无需手动启动 sunshine.exe；确认 Sunshine 服务后台运行
2. Windows 保持实体屏 + VDD 的扩展状态
3. 打开 iPad 或 Android 上的 Moonlight
4. 点击主机，再点击 Desktop 或游戏
5. 实体屏应熄灭，客户端正常显示
6. 玩完后在 Moonlight 菜单选择 Quit Session
7. 等待约 3 秒，实体屏恢复

### 维护检查清单

- 只保留一个启用的 Virtual Display Driver
- Windows 显示设置为扩展模式
- Sunshine 服务开机自动运行
- `output_name` 指向正确的 VDD device_id
- 大版本显卡/芯片组驱动升级前先卸载 VDD，升级完成后重新安装并重新确认 device_id
- device_id 变化后必须更新 `output_name`
