## 一、核心原理

内网穿透的本质是：**让内网设备主动发起连接，建立一条到公网服务器的 "秘密通道"**。此后，公网服务器将特定端口的流量通过这个通道转发给内网设备。

类比理解：你在管理严格的 "小区" 里开了一家 "私房菜馆"（本地电脑），外面的人没法直接进来。于是你主动给 "市中心办公室"（云服务器）打一个专属内线电话并保持通话，告诉前台："如果有人来前台找 9090 号服务，就把请求通过这条内线转给我处理。"

数据流向：

```
[公网访客] ---> [云服务器 :9090] ---> [反向隧道] ---> [内网 :8080]
```

## 二、方案一：SSH 反向隧道 (最经典，零额外软件)

这是最经典的方法，几乎所有的 Linux 云服务器都自带 SSH 服务，本地电脑也都有 SSH 客户端，无需额外安装软件。

### 2.1 前提条件

- 本地电脑安装了 SSH 客户端（Windows 10/11 的 PowerShell/CMD 自带 `ssh` 命令）
- 知道云服务器的 IP 地址、用户名和密码/密钥

### 2.2 第一步：在云服务器上开启 GatewayPorts

这一步非常关键却容易被忽略。默认情况下 SSH 隧道在服务器上只监听 `127.0.0.1`，需要让它监听所有网络接口（`0.0.0.0`）才能从公网访问。

```bash
# SSH 登录到云服务器
ssh user@your_cloud_server_ip

# 编辑 SSH 服务配置
sudo nano /etc/ssh/sshd_config
```

在文件末尾添加或修改：

```
GatewayPorts yes
```

保存后重启 SSH 服务：

```bash
sudo systemctl restart sshd
```

^gateway-ports

这一步在云服务器上只需要做一次。

### 2.3 第二步：在本地电脑建立反向隧道

在本地电脑终端执行：

```bash
ssh -R 9090:localhost:8080 user@your_cloud_server_ip
```

参数解释：

| 参数 | 含义 |
|------|------|
| `-R` | Reverse Tunnel（反向隧道）标志，核心参数 |
| `9090` | 在云服务器上开放的公网端口 |
| `localhost:8080` | 本地电脑上运行的服务地址和端口 |
| `user@your_cloud_server_ip` | 云服务器登录信息 |

**重要：不要关闭这个终端窗口！** 只要 SSH 连接保持活动，隧道就通。关闭窗口或 `Ctrl+C` 会断开隧道。

### 2.4 第三步：配置云服务器安全组

登录云服务商控制台（阿里云、腾讯云等），找到服务器实例的安全组 / 防火墙配置，添加入站规则，允许所有来源 `0.0.0.0/0` 访问你设置的公网端口（如 9090）。

### 2.5 验证

在浏览器中访问 `http://your_cloud_server_ip:9090`，请求会通过云服务器穿过 SSH 隧道到达你本地电脑的 8080 端口。

**优缺点：**

| 优点 | 缺点 |
|------|------|
| 无需额外软件 | 容易断开，需手动重连 |
| 安全加密 | 需要配置 GatewayPorts |
| 快速上手 | 不适合长期使用 |

### 2.6 autossh 持久化方案

由于纯 SSH 隧道断开后不会自动重连，使用 `autossh` 来守护连接。

**安装 autossh：**

```bash
# Debian/Ubuntu
sudo apt update && sudo apt install autossh

# CentOS/RHEL
sudo yum install autossh
```

**配置 SSH 密钥免密登录：**

```bash
# 在本地生成密钥对
ssh-keygen -t rsa

# 复制公钥到云服务器
ssh-copy-id user@your_cloud_server_ip
```

**使用 autossh 建立隧道：**

```bash
autossh -M 20000 -fN -R 2222:localhost:22 user@your_cloud_server_ip
```

参数解释：

| 参数 | 含义 |
|------|------|
| `-M 20000` | autossh 监控端口（使用 20000 和 20001 检测连接状态） |
| `-f` | 在后台运行 |
| `-N` | 不执行远程命令，仅端口转发 |
| `-R 2222:localhost:22` | 将云服务器 2222 端口映射到本地 22 端口 |

### 2.7 systemd 服务实现开机自启

在内网笔记本上创建 systemd 服务文件：

```bash
sudo nano /etc/systemd/system/autossh-tunnel.service
```

写入以下内容（注意替换用户名和 IP）：

```ini
[Unit]
Description=AutoSSH tunnel to public server
After=network.target

[Service]
User=user_private
Group=user_private
ExecStart=/usr/bin/autossh -M 0 -o "ServerAliveInterval=30" -o "ServerAliveCountMax=3" -N -R 2222:localhost:22 root@公网IP
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

^autossh-service

说明：
- `-M 0` 表示关闭 autossh 自己的监控端口，完全依赖 SSH 自身的保活机制
- `ServerAliveInterval=30` 每 30 秒发送一次心跳
- `ServerAliveCountMax=3` 连续 3 次心跳失败则判定断开
- 注意 `ExecStart` 中不要加 `-f`，因为 systemd 会管理后台进程

启用并启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable autossh-tunnel.service
sudo systemctl start autossh-tunnel.service
sudo systemctl status autossh-tunnel.service
```

### 2.8 从公网连接内网 SSH

隧道打通后，从任何能上网的电脑：

```bash
ssh user_private@PUBLIC_IP -p 2222
```

## 三、方案二：frp (功能最强，完全可控)

frp 是一个专门为内网穿透而生的开源工具，非常稳定且功能强大。适用于长期、稳定地从外网访问家中的 NAS、树莓派、Windows 远程桌面等。

### 3.1 准备工作

- 一台有公网 IP 的云服务器 (VPS)，最低配置即可，操作系统为 Linux（Ubuntu 或 CentOS）
- 一个域名 (可选)

### 3.2 在云服务器上配置 frps（服务端）

**下载 frp：**

```bash
# SSH 登录到 VPS
# 访问 https://github.com/fatedier/frp/releases 获取最新版
wget https://github.com/fatedier/frp/releases/download/v0.58.1/frp_0.58.1_linux_amd64.tar.gz
tar -zxvf frp_0.58.1_linux_amd64.tar.gz
cd frp_0.58.1_linux_amd64
```

**编辑服务端配置 `frps.ini`：**

```bash
vim frps.ini
```

最简配置：

```ini
[common]
bind_port = 7000
```

^frps-minimal

**启动服务端：**

```bash
./frps -c ./frps.ini
```

看到 `frps started successfully` 表示成功。

后台运行：

```bash
nohup ./frps -c ./frps.ini &
```

**重要：去云服务商控制台的防火墙 / 安全组设置里，放行 TCP 的 7000 端口**，以及后续你需要用到的其他端口（如 8080）。

### 3.3 在内网设备上配置 frpc（客户端）

同样下载解压对应版本的 frp，然后编辑 `frpc.ini`：

```ini
[common]
server_addr = 你的VPS公网IP
server_port = 7000

[web_server_1]
type = http
local_ip = 127.0.0.1
local_port = 80
custom_domains = www.你的域名.com

[ssh_access]
type = tcp
local_ip = 127.0.0.1
local_port = 22
remote_port = 6000
```

^frpc-config

配置解释：

| 块 | 含义 |
|----|------|
| `[common]` | 填入 VPS 的 IP 和端口 7000 |
| `[web_server_1]` | HTTP 穿透示例。`local_port = 80` 为内网服务端口；`custom_domains` 需将域名 A 记录解析到 VPS IP |
| `[ssh_access]` | TCP 穿透示例。将 VPS 上 6000 端口映射到内网 22 端口 |

**启动客户端：**

```bash
./frpc -c ./frpc.ini
```

后台运行可以使用 `nohup` 或配置为 systemd 服务。

### 3.4 验证

- **Web 服务**：在浏览器中访问 `http://你的VPS公网IP:remote_port` 或配置的域名
- **SSH 服务**：`ssh -p 6000 user@你的VPS公网IP`

## 四、方案三：ngrok (最简单，5 分钟搞定)

适用于临时演示、开发调试、Webhook 回调测试等场景。

### 4.1 注册并获取 AuthToken

1. 访问 [ngrok 官网](https://ngrok.com/)，使用邮箱或 Google/GitHub 账号注册
2. 登录后在仪表盘左侧找到 **"Your Authtoken"**，复制认证令牌

### 4.2 下载并连接账户

在 [ngrok 下载页面](https://ngrok.com/download) 下载适合你操作系统的客户端。

```bash
ngrok config add-authtoken [你的AuthToken]
```

这个步骤只需做一次。

### 4.3 启动穿透

```bash
# 将本地 80 端口暴露到公网
ngrok http 80

# 或者暴露 3000 端口
ngrok http 3000
```

^ngrok-command

终端会显示类似如下信息：

```
Session Status                online
Forwarding                    https://random-string-abcd.ngrok-free.app -> http://localhost:80
```

`Forwarding` 那一行的 `https://xxx.ngrok-free.app` 就是 ngrok 为你生成的公网地址，发给别人就能访问到本地服务。

**注意：** 免费版每次启动生成的域名是随机的，关闭终端即断开。

## 五、方案四：ZeroTier (构建虚拟局域网)

适用于不想暴露任何端口到公网，而是将多台设备（公司电脑、家庭电脑、手机）组成一个安全私有网络，让它们像在同一路由器下一样互访。

### 5.1 创建网络

1. 访问 [my.zerotier.com](https://my.zerotier.com/) 注册登录
2. 点击 **"Create A Network"**，系统自动分配一个 16 位网络 ID

### 5.2 安装客户端并加入网络

在每台设备上从 [ZeroTier 下载页面](https://www.zerotier.com/download/) 安装客户端。

安装后打开客户端，找到 **"Join New Network"**，输入 16 位网络 ID 加入。

### 5.3 授权设备

回到 [my.zerotier.com](https://my.zerotier.com/) 的网络管理页面，在 **"Members"** 区域勾选待授权设备前面的 **"Auth?"** 复选框。

授权后 ZeroTier 会为每台设备分配虚拟内网 IP（例如 `10.147.17.21`）。

### 5.4 验证

```bash
# 在笔记本上 ping 家里电脑的虚拟 IP
ping 10.147.17.21

# 通过 SSH 连接家里的 Linux 主机
ssh user@10.147.17.21

# 访问 Windows 共享文件夹
# 在文件管理器地址栏输入 \\10.147.17.22
```

## 六、实际场景：香港服务器做跳板访问内网笔记本

### 场景假设

| 设备 | IP | 用户名 |
|------|-----|--------|
| 香港服务器 (公网) | `PUBLIC_IP` | `user_public` |
| 笔记本服务器 (内网) | `192.168.x.x` | `user_private` |

### 步骤

**1）香港服务器配置（一次性）：**

同 [[#^gateway-ports|方案一的第一步]]，设置 `GatewayPorts yes` 并重启 sshd。

**2）内网笔记本建立反向隧道：**

```bash
ssh -fN -R 2222:localhost:22 user_public@PUBLIC_IP
```

- `-f`：SSH 连接成功后转入后台运行
- `-N`：不执行远程命令
- `-R 2222:localhost:22`：将香港服务器 2222 端口映射到本地 22 端口

**3）从公网连接内网服务器：**

```bash
ssh user_private@PUBLIC_IP -p 2222
```

注意：这里的 `user_private` 是内网笔记本的用户名，密码也是内网笔记本的密码。

**4）autossh 持久化 + systemd 开机启动：**

见 [[#^autossh-service|autossh systemd 服务配置]]

### 安全建议

- 在香港服务器上使用防火墙（如 `ufw`）只开放必要的端口（22、2222 等）
- 两台服务器上都禁用密码登录，仅使用 SSH 密钥登录
- 不要使用过于常见的端口作为隧道监听端口

## 七、通过服务器代理上网：SSH 本地端口转发

### 场景

你在香港服务器上部署了一个监听在 `127.0.0.1:1080` 的 SOCKS5 代理（例如 Docker 中运行的 WARP 代理）。你希望本地电脑通过这个代理上网。

### 建立本地端口转发隧道

在本地电脑终端执行：

```bash
ssh -N -L 1080:127.0.0.1:1080 user@your_hk_server_ip
```

参数解释：

| 参数 | 含义 |
|------|------|
| `-N` | 不执行远程命令，只建立隧道 |
| `-L 1080:127.0.0.1:1080` | 本地端口转发。第一个 `1080` 是本地监听端口；`127.0.0.1:1080` 是远程目标地址 |
| `user@your_hk_server_ip` | 香港服务器登录信息 |

^local-forward

此命令的含义是："将我本地电脑 1080 端口收到的所有流量，通过 SSH 加密通道，原封不动地转发给远程服务器的 `127.0.0.1:1080` 端口。"

**保持连接：** 执行命令后终端窗口不要关闭。关闭窗口就等于挂断通道。

### 配置浏览器使用此代理

以 SwitchyOmega / FoxyProxy 浏览器插件为例：

| 配置项 | 值 |
|--------|-----|
| 协议 (Protocol) | `SOCKS5` |
| 服务器 (Server/Host) | `127.0.0.1` |
| 端口 (Port) | `1080` |

**特别注意：** 服务器地址填的是 `127.0.0.1`（你自己的本地电脑），而不是香港服务器的 IP。因为你连接的是在本地创建的 SSH 隧道入口。

数据全路径：

```
[本地浏览器] --> socks5://127.0.0.1:1080 --> [SSH加密隧道] --> [香港服务器 127.0.0.1:1080] --> [WARP/代理服务] --> [目标网站]
```

^proxy-chain

### 验证

打开浏览器访问 [ipinfo.io](https://ipinfo.io)，显示的 IP 应为香港（或代理的出口 IP）。
