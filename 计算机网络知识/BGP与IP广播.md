## 一、BGP 核心概念

### 1.1 什么是 BGP

**BGP (Border Gateway Protocol，边界网关协议)** 是互联网的核心路由协议。准确地说，"广播" IP 的正式术语是 **宣告 (Announce)** 或 **通告 (Advertise)**。它不像 Wi-Fi 那样向空中广播，而是一个精确的、逐级传递的通告过程。

### 1.2 三大核心要素

在宣告 BGP 路由之前，你必须拥有：

| 要素 | 解释 |
|------|------|
| **自治系统号 (ASN)** | 你网络的 "身份证号"。互联网由一个个独立的自治系统 (AS) 组成，每个 AS 有全球唯一的编号。 |
| **IP 地址前缀 (IP Prefix)** | 你要宣告的 IP 地址段，例如 `198.51.100.0/24`。你必须合法拥有该 IP 段的使用权，通常从 RIR（如 APNIC, RIPE, ARIN）申请。 |
| **BGP 邻居 (BGP Peer)** | 你不能凭空向互联网广播。你必须至少与一个其他 AS（通常是上游 ISP / Transit Provider）建立 BGP 连接。 |

### 1.3 自治系统之间的关系

```
互联网
  |
  ├── AS1 (Tier 1 骨干网, 如 Lumen / Arelion / Cogent)
  │     ├── AS2 (大型 ISP)
  │     │     ├── AS3 (中小型 ISP)
  │     │     │     └── AS64500 (你的网络)
  │     │     └── AS4 (数据中心)
  │     └── AS5 (Cloudflare - AS13335)
  └── AS6 (Google 等大型科技公司)
```

## 二、BGP 宣告的详细步骤

假设你已拥有 `AS64500` 和 IP 前缀 `198.51.100.0/24`，且已与上游 ISP `AS64501` 签署协议。

### 2.1 步骤一：配置 BGP 路由器

在你的网络边界路由器上进行 BGP 配置（概念性伪代码）：

```
// 1. 启动 BGP 进程，定义自己的 ASN
bgp_process_start (my_asn: 64500);

// 2. 定义要宣告的 IP 前缀
bgp_network_announce (prefix: "198.51.100.0/24");

// 3. 定义 BGP 邻居（上游 ISP）
bgp_add_neighbor (
  neighbor_ip: "203.0.113.1",  // ISP 路由器的 IP
  neighbor_asn: 64501           // ISP 的 ASN
);
```

### 2.2 步骤二：建立 BGP 会话（邻居之间的 "握手"）

1. **TCP 连接：** 你的路由器向邻居路由器 IP 的 TCP 端口 **179** 发起连接请求
2. **OPEN 消息：** 连接建立后，双方互发 OPEN 消息，包含各自的 ASN，相当于 "交换名片"
3. **会话建立：** 双方接受对方的 OPEN 消息后，BGP 会话进入 **Established**（已建立）状态，准备交换路由信息

### 2.3 步骤三：发送 UPDATE 消息（真正的 "广播" 动作）

会话建立后，你的路由器向邻居发送 **UPDATE 消息**，这是整个过程的核心。消息包含：

**前缀：** `198.51.100.0/24`

**路径属性 (Path Attributes)：**

| 属性 | 说明 | 示例值 |
|------|------|--------|
| **AS_PATH** | 路由通告经过的 AS 列表。BGP 防环路的关键机制 | `[64500]`（你的 ASN） |
| **NEXT_HOP** | 告诉邻居发数据包到哪个 IP | 你路由器的入口 IP |
| **ORIGIN** | 标记路由来源 | 从你网络内部产生 |

**通俗解释：**

> "你好，邻居 AS64501！我这里有一条新路，通往 198.51.100.0/24。要走这条路，请把数据包发给我，路径是 [64500]。"

### 2.4 步骤四：路由的传播 (Propagation)

你的上游 ISP (AS64501) 收到 UPDATE 消息后会：

1. **验证策略：** 检查与你签订的协议，确认你有权宣告该 IP 前缀（防止路由劫持）。现代网络通常使用 **RPKI** 技术自动验证。
2. **处理并转发：** 验证通过后，AS64501 将这条路由转发给它自己的所有 BGP 邻居。转发前，把自己的 ASN 加在 AS_PATH 的最前面。新的 AS_PATH 变为 `[64501, 64500]`
3. **全球扩散：** 各级 ISP 重复此过程：验证 -> AS_PATH 加自己的 ASN -> 继续转发

这个过程像涟漪一样扩散，几分钟内全球互联网骨干路由器都会收到这条路由。例如，地球另一端的某个 AS 可能收到：

```
AS_PATH: [AS1, AS2, AS3, AS64501, 64500]
Prefix: 198.51.100.0/24
```

它的路由器查表后知道："要访问 `198.51.100.0/24`，发数据包给邻居 AS1，它会一步步传下去到达 AS64500。"

**至此，你的 IP 段成功地宣告给了全世界，互联网知道了如何找到你。**

## 三、BGP 服务商分类

### 3.1 大型云平台（最灵活，适合虚拟化 / 云环境）

允许将自有 IP 段（BYOIP）用于云服务器（VM），无需物理硬件。

| 服务商 | 特点 |
|--------|------|
| **Cloudflare** (AS13335) | Magic Transit 企业服务，全球最大网络之一，DDoS 清洗，无与伦比的全球网络性能 |
| **Vultr** | 对个人 / 小型开发者友好，明确提供 BGP 服务和 BYOIP，价格透明，门槛较低 |
| **AWS** | 允许 BYOIP 与 EC2 等资源关联，功能全面 |
| **Google Cloud** | 类似 BYOIP 功能 |
| **Azure** | 支持客户自带 IP 地址 |

### 3.2 传统数据中心 (IDC) 和主机托管 (Colocation)

提供物理机柜、电力和网络连接，让你放置自己的物理服务器。

| 服务商 | 特点 |
|--------|------|
| **Equinix** | 全球最大的数据中心提供商之一，丰富的网络连接 |
| **Digital Realty** | 全球领先的数据中心巨头 |
| **CoreSite** | 主要在美国运营 |
| **本地 IDC** | 几乎每个国家 / 地区都有本地数据中心运营商 |

### 3.3 骨干网 / 一级传输商 (Tier 1 Network)

互联网的 "主干道"，主要为大型 ISP 和超大型企业提供 BGP 传输服务，价格昂贵，不直接服务个人或中小企业。

| 服务商 | 说明 |
|--------|------|
| **Lumen** (原 Level 3) | 北美骨干 |
| **Arelion** (原 Telia Carrier) | 欧洲 / 全球骨干 |
| **Cogent Communications** | 全球骨干 |
| **NTT Communications** | 亚洲 / 全球骨干 |
| **GTT** | 全球骨干 |

### 3.4 选择建议

| 类别 | 代表服务商 | 适合场景 | 技术复杂度 | 成本 |
|------|-----------|---------|-----------|------|
| 云平台 / VPS | Cloudflare, AWS, Google Cloud, **Vultr** | 最灵活，无需物理硬件 | 中等（文档齐全） | 相对较低，按需付费 |
| 数据中心 / 托管 | Equinix, Digital Realty | 需要部署自己的物理服务器 | 较高（需硬件和网络知识） | 高（机柜、电力、带宽） |
| 骨干传输商 | Lumen, Arelion, Cogent | 大型 ISP 或跨国企业 | 极高（专业网络工程师团队） | 极高 |

## 四、Cloudflare Magic Transit 与 BYOIP

### 4.1 核心机制

Cloudflare 通过 **Magic Transit** 和 **BYOIP** 服务，允许企业客户将自己合法拥有的 IP 地址段交由 Cloudflare 管理，Cloudflare 会通过其全球网络（AS13335）为客户宣告这些 IP 地址，同时提供 DDoS 清洗等安全服务。

### 4.2 典型应用：获取 "冷门 IP 归属地"

流程：

```
1. 获得注册在 "马绍尔群岛" 的合法 IP 段（从 APNIC/RIPE/ARIN 申请）
2. 使用 Cloudflare BYOIP 服务，授权 Cloudflare 在全球宣告此 IP 段
3. Cloudflare 通过 AS13335 向全球做 BGP 宣告
4. 实际效果：
   - 物理层面：流量路由到离用户最近的 Cloudflare 数据中心（如美国洛杉矶），速度极快
   - 地理显示：IP 查询时归属地仍是 IP 注册机构登记的 "马绍尔群岛"
```

^cold-ip-use-case

这实现了 **"物理位置" 和 "注册位置" 的完美分离**。Bilibili 等平台查询 IP 的 "户口" 时，查到的是 RIR 注册的位置。

### 4.3 Cloudflare WARP（面向个人）

Cloudflare WARP 是面向个人的免费应用（有 WARP+ 付费版），功能类似 VPN。开启后流量导向 Cloudflare 网络，对外 IP 变成 Cloudflare 节点的 IP。

**但 WARP 不能获得特定地区的 IP。** Cloudflare 会自动将用户连接到最近的或延迟最低的数据中心。获取特定区域的 IP 需要 BYOIP + Magic Transit 的企业级方案。

## 五、BGP 安全机制

### 5.1 RPKI (Resource Public Key Infrastructure)

RPKI 是用于防路由劫持的安全基础设施。它允许 IP 地址的合法持有者通过加密签名的方式，声明哪些 AS 有权宣告某个 IP 前缀。

```
IP 持有者 -> 签署 ROA (Route Origin Authorization) -> RPKI 仓库
路由器 -> 查询 RPKI -> 验证收到的 BGP 宣告是否合法
```

### 5.2 路由劫持风险

如果没有 BGP 安全机制，恶意方可能宣告不属于自己的 IP 段，将流量导向自己的网络。这是 BGP 设计之初就存在的信任问题，RPKI 正在逐步解决。

---

## 六、重要前提

无论选择哪家服务商，你都必须先合法拥有：

1. **IP 地址段：** 从 RIR（APNIC / RIPE / ARIN / LACNIC / AFRINIC）申请的可移植 IP 段
2. **ASN：** 自治系统号

这些服务商只是提供平台让你 "广播"，它们不会为你提供 IP 段本身。
