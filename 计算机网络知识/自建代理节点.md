## 一、方案总览

自建代理节点有几种主流方案，按复杂度和需求递增：

| 方案 | 终端覆盖 | 难度 | 隐蔽性 | 适用场景 |
|------|---------|------|--------|---------|
| SSH SOCKS5 代理 | 仅浏览器 | 极低 | 低（大量 SSH 流量特征明显） | 临时使用、快速验证 |
| WireGuard VPN | 全局 | 低 | 中 | 个人日常全局上网 |
| OpenVPN | 全局 | 中 | 中 | 兼容性要求高的场景 |
| VLESS + XTLS-Reality | 全局 + 分流 | 中 | 高（Reality 模拟正常 HTTPS 流量） | 长期使用、需要抗检测 |

---

## 二、方案一：SSH SOCKS5 动态端口转发（最快速）

### 2.1 原理

通过 SSH 的 `-D` 参数在本地建立一个 SOCKS5 代理，流量经由 SSH 加密隧道到达海外服务器后出口。无需在服务器上安装任何额外的代理软件。

```
[本地应用] -> socks5://127.0.0.1:1080 -> [SSH加密隧道] -> [海外服务器] -> [目标网站]
```

### 2.2 建立代理

在本地 Windows 电脑打开 PowerShell / CMD / Git Bash：

```bash
ssh -D 1080 -N -f user@your_server_ip
```

参数解释：

| 参数 | 含义 |
|------|------|
| `-D 1080` | 在本地 1080 端口创建一个 SOCKS 动态代理 |
| `-N` | 不执行远程命令，仅用于端口转发 |
| `-f` | SSH 连接在后台运行 |
| `user@your_server_ip` | 海外服务器的用户名和 IP |

执行成功后，本地 `127.0.0.1:1080` 就有了一个 SOCKS5 代理。

### 2.3 配置系统代理

#### 方式一：Windows 设置（推荐）

1. 打开 **设置** -> **网络和 Internet** -> **代理**
2. 在 "手动设置代理" 部分，打开 **使用代理服务器**
3. 地址：`127.0.0.1`，端口：`1080`
4. 保存

#### 方式二：Internet 选项

1. `Win + R` -> 输入 `inetcpl.cpl` -> 回车
2. **连接** -> **局域网设置**
3. 勾选 "为 LAN 使用代理服务器"
4. 点击 **高级**，在 Socks 字段填：地址 `127.0.0.1`，端口 `1080`
5. 其他协议（HTTP/HTTPS/FTP）留空

#### 方式三：仅浏览器（推荐日常使用）

安装浏览器代理管理插件，按需切换：

- Chrome / Edge：安装 **SwitchyOmega**
- Firefox：安装 **FoxyProxy Standard**

新建代理情景模式：

| 配置项 | 值 |
|--------|-----|
| 协议 | `SOCKS5` |
| 服务器 | `127.0.0.1` |
| 端口 | `1080` |

^socks5-browser

### 2.4 验证

打开浏览器访问 [ip.sb](https://ip.sb) 或 [whatismyip.com](https://whatismyip.com)，显示的 IP 应为海外服务器的 IP。

### 2.5 注意事项

- **连接稳定性：** SSH 连接断开则代理失效。网络不稳时体验差。
- **服务器带宽：** 持续的代理流量会占用服务器带宽。
- **安全性：** 使用 SSH 密钥对认证而不是密码，禁用密码登录。
- **持久化：** 本地电脑重启后需重新执行 `ssh -D` 命令。

## 三、方案二：WireGuard VPN（个人推荐）

WireGuard 性能优异，配置简单，是替代传统 VPN 的最佳选择。以下使用 Nyr 的一键安装脚本。

### 3.1 服务器端安装

在海外 VPS（Ubuntu 20.04+ / Debian）上：

```bash
# SSH 登录
ssh user@your_server_ip

# 更新系统
sudo apt update && sudo apt upgrade -y

# 下载并运行安装脚本
wget https://git.io/wireguard -O wireguard-install.sh
sudo chmod +x wireguard-install.sh
sudo bash wireguard-install.sh
```

脚本交互提示：

| 提示 | 操作 |
|------|------|
| 公网 IPv4 地址 | 回车确认（自动检测） |
| 监听端口 | 默认 51820，可改（如 UDP 23333），回车 |
| DNS 解析器 | 推荐选 `1.1.1.1`（Cloudflare DNS） |
| 客户端名称 | 例如 `my_laptop` |

脚本自动完成：安装 WireGuard、生成密钥对、配置服务器端、生成客户端配置文件。

### 3.2 获取客户端配置文件

配置文件路径：`/root/my_laptop.conf`

**方法一：scp 下载到本地（在本地终端执行）：**

```bash
scp user@your_server_ip:/root/my_laptop.conf .
```

**方法二：cat 直接复制：**

```bash
cat /root/my_laptop.conf
# 复制输出的全部内容，保存为 my_laptop.conf
```

### 3.3 客户端配置

**Windows / macOS / Linux 桌面版：**
1. 从 [WireGuard 官网](https://www.wireguard.com/install/) 下载安装客户端
2. 打开客户端，选择 **导入隧道** 或 **从文件导入**
3. 选择 `.conf` 文件，激活连接

**Android / iOS：**
1. 应用商店下载 WireGuard
2. 点 "+" -> 从文件导入或扫描二维码

### 3.4 客户端管理

再次运行脚本可进行管理：

```bash
sudo bash wireguard-install.sh
```

会提示：
- 添加新客户端
- 删除现有客户端
- 卸载 WireGuard

### 3.5 防火墙设置

脚本通常自动配置防火墙。但如果服务器有外部安全组（如 AWS Security Groups、阿里云安全组），需手动放行 WireGuard 使用的 UDP 端口（默认 51820）。

## 四、方案三：VLESS + XTLS-Reality + 3x-ui 面板（进阶抗检测）

VLESS + Reality 是当前抗检测能力最强的代理方案。Reality 通过 "借用了别人的 TLS 证书" 来模拟正常 HTTPS 网站的流量特征，使得代理流量在墙的视角里看起来就像在访问一个普通网站。

### 4.1 安装 3x-ui 面板

3x-ui 是 xray-core 的 Web 管理面板，可以直观地配置 VLESS / VMess / Trojan 等协议。

```bash
# 一键安装脚本
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

安装完成后：
- Web 面板地址：`http://your_server_ip:2053` 或你设定的端口
- 首次登录需要设置用户名密码

### 4.2 配置 VLESS + Reality 节点

在 3x-ui Web 面板中：

1. **添加入站 (Add Inbound)**

   | 配置项 | 值 |
   |--------|-----|
   | 协议 | `vless` |
   | 端口 | `443` 或自选端口 |
   | Reality | 开启 |
   | Flow | `xtls-rprx-vision` |
   | 传输 | `tcp` |

2. **Reality 配置**

   | 配置项 | 值 |
   |--------|-----|
   | Dest (目标网站) | `www.microsoft.com:443` 或 `www.apple.com:443`（选一个真实的 HTTPS 站点，Reality 会借用它的 TLS 指纹） |
   | Server Name | 与 Dest 域名一致 |
   | Private Key | 点击生成 |
   | Public Key | 自动从 Private Key 得出 |
   | Short ID | 随机六位十六进制 |

3. **获取连接信息**

   面板会生成类似这样的 VLESS 链接：

   ```
   vless://UUID@SERVER_IP:443?encryption=none&flow=xtls-rprx-vision&security=reality&sni=www.microsoft.com&fp=chrome&pbk=PUBLIC_KEY&sid=SHORT_ID&spx=%2F#NODE_NAME
   ```

### 4.3 客户端配置

#### v2rayN (Windows)

1. 下载 [v2rayN](https://github.com/2dust/v2rayN/releases)，需要配合 Xray-core
2. 打开 v2rayN -> 服务器 -> 添加 VLESS 服务器
3. 填入面板生成的各项参数（address, port, uuid, flow, publicKey, shortId, sni 等）
4. 右键系统托盘图标 -> 开启系统代理

#### Clash Meta (跨平台，支持分流)

Clash 配置文件示例（config.yaml 片段）：

```yaml
proxies:
  - name: "HK-Reality"
    type: vless
    server: YOUR_SERVER_IP
    port: 443
    uuid: YOUR_UUID
    network: tcp
    tls: true
    flow: xtls-rprx-vision
    reality-opts:
      public-key: YOUR_PUBLIC_KEY
      short-id: YOUR_SHORT_ID
    client-fingerprint: chrome
    servername: www.microsoft.com

proxy-groups:
  - name: "Proxy"
    type: select
    proxies:
      - "HK-Reality"
      - DIRECT

rules:
  - DOMAIN-SUFFIX,google.com,Proxy
  - GEOIP,CN,DIRECT
  - MATCH,Proxy
```

^clash-reality-config

### 4.4 为什么选择 Reality

| 特性 | 说明 |
|------|------|
| 无需域名和 TLS 证书 | 直接借用目标网站的证书 |
| 流量伪装 | 从墙的视角看，你在访问微软 / 苹果官网 |
| 不需要 CDN | 直连，延迟低 |
| 抗主动探测 | 没有代理特有的握手特征 |

## 五、额外方案：Docker + Cloudflare WARP 出口代理

### 5.1 场景

在香港服务器上部署 WARP 代理，使所有出站流量通过 Cloudflare 节点出口，可以获得特定区域的出口 IP（如澳门 MO）。

### 5.2 原理

通过锁定 Cloudflare WARP 底层 WireGuard 的 `Endpoint` IP 地址，精确控制流量出口地理位置。WARP 使用 WireGuard 协议，Endpoint 决定了流量从哪个 Cloudflare 节点出口。

### 5.3 安装 Docker（官方现代方法）

```bash
# Debian/Ubuntu
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$UBUNTU_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 用户权限
sudo usermod -aG docker ${USER}
# 注销重登或 newgrp docker 使生效
```

^docker-install

**注意：** 使用 `docker compose`（无连字符，v2），而不是已废弃的 `docker-compose`（有连字符，v1）。

### 5.4 部署 WARP SOCKS5 代理（以 kingcc/warproxy 为例）

**创建项目目录：**

```bash
mkdir -p ~/warp-macau/config
cd ~/warp-macau
```

**编写 `docker-compose.yml`：**

```yaml
version: '3.8'

services:
  warproxy:
    image: ghcr.io/kingcc/warproxy:latest
    container_name: warp-macau-proxy
    restart: always
    ports:
      # 只允许本机访问，确保安全
      - "127.0.0.1:1080:1080"
    volumes:
      - ./config:/config
    cap_add:
      # WireGuard 必需
      - NET_ADMIN
    environment:
      - TZ=Asia/Macau
      # 如需认证则取消注释：
      # - USERNAME=your_user
      # - PASSWORD=your_password
```

^docker-compose-warp

**首次启动生成配置文件：**

```bash
docker compose up -d
# 等待约 30 秒
ls -l ./config
# 确认看到 wgcf-account.toml 和 wgcf-profile.conf
```

**扫描并锁定澳门端点 IP：**

```bash
# 下载端点扫描脚本
wget -N https://gitlab.com/Misaka-blog/warp-script/-/raw/main/files/warp-yxip/warp-yxip.sh
chmod +x warp-yxip.sh
./warp-yxip.sh
cat result.csv
# 查找 Location 列为 MAC 或 Macau 的 IP，例如 104.28.224.109:2408
```

**修改 WireGuard 配置：**

```bash
docker compose down
nano ./config/wgcf-profile.conf
```

找到 `Endpoint =` 行，替换为澳门 IP：

```
Endpoint = 104.28.224.109:2408
```

保存退出。

**重启并验证：**

```bash
docker compose up -d
sleep 15
curl --proxy socks5h://127.0.0.1:1080 https://ipinfo.io
```

期望返回 `"country": "MO"`。

### 5.5 kingcc/warproxy 关键环境变量

| 环境变量 | 描述 | 默认值 |
|---------|------|--------|
| `SOCKS5_PORT` | SOCKS5 代理监听端口 | `1080` |
| `HTTP_PORT` | HTTP 代理监听端口（默认不启用） | `None` |
| `USERNAME` | 代理认证用户名 | `None` |
| `PASSWORD` | 代理认证密码 | `None` |
| `TZ` | 容器时区 | `Asia/Shanghai` |
| `WARP_PLUS` | 是否启用自动刷新 WARP+ 流量 | `true` |
| `VERBOSE` | 是否显示详细日志 | `false` |

### 5.6 服务管理

```bash
# 进入项目目录
cd ~/warp-macau

# 启动服务（后台模式）
docker compose up -d

# 停止服务（不删除容器）
docker compose stop

# 重启服务
docker compose restart

# 查看实时日志
docker compose logs -f

# 停止并移除容器、网络（保留配置文件）
docker compose down

# 彻底清理
docker compose down
cd .. && rm -rf ~/warp-macau
```

### 5.7 端点失效修复流程

This 方案依赖的端点 IP 可能被 Cloudflare 调整。当代理无法连接或出口 IP 不是澳门时：

```bash
cd ~/warp-macau
docker compose down           # 1. 停止容器
./warp-yxip.sh                # 2. 重新扫描
cat result.csv                # 3. 找到新的澳门 IP
nano ./config/wgcf-profile.conf   # 4. 更新 Endpoint 地址
docker compose up -d          # 5. 重启服务
sleep 15
curl --proxy socks5h://127.0.0.1:1080 https://ipinfo.io  # 6. 验证
```

## 六、客户端全局代理配置

### 6.1 终端命令行环境变量

```bash
export ALL_PROXY=socks5h://127.0.0.1:1080
export HTTP_PROXY=$ALL_PROXY
export HTTPS_PROXY=$ALL_PROXY
```

### 6.2 curl

```bash
curl --proxy socks5h://127.0.0.1:1080 https://ipinfo.io
```

### 6.3 git

```bash
git config --global http.proxy 'socks5://127.0.0.1:1080'
# 取消代理
git config --global --unset http.proxy
```
