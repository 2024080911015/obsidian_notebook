## 一、视频资源嗅探

### 使用 Chrome 扩展嗅探

在 Manifest V3 下，最强大的嗅探方式是 `chrome.debugger` API。它能像开发者工具 Network 面板一样监控所有网络请求。

**manifest.json：**

```json
{
  "manifest_version": 3,
  "name": "Video Sniffer",
  "version": "1.0",
  "permissions": ["debugger", "activeTab", "storage"],
  "action": { "default_popup": "popup.html" },
  "background": { "service_worker": "background.js" }
}
```

^sniffer-manifest

**工作原理：**

1. 插件请求 `debugger` 权限（敏感的权限，安装时会显示警告）
2. 点击插件图标时，通过 `chrome.debugger.attach` 附加到当前标签页
3. 浏览器顶部出现黄色提示条（"xxx is debugging this browser"，无法禁用）
4. 通过 `chrome.debugger.sendCommand` 发送 CDP 命令，启用 `Network.enable`
5. 通过 `chrome.debugger.onEvent` 监听 `Network.requestWillBeSent` 和 `Network.responseReceived` 事件
6. 在事件中过滤 URL 以 `.mp4`, `.flv`, `.m3u8`, `.mpd` 结尾的请求

**优点**：功能强大，可嗅探几乎所有类型的网络请求。**缺点**：侵入性强（黄色警告条），权限要求高，实现复杂。

### 备用方法：Content Script 分析 HTML

更简单但局限性大：

```javascript
// 注入到目标页面的 content script
const videoElements = document.querySelectorAll('video');
for (const video of videoElements) {
    console.log('Video src:', video.src);
}
```

**局限**：现代视频网站使用 MSE（Media Source Extensions）和 HLS/DASH 流媒体，`<video>` 标签的 `src` 通常是 `blob:` 链接，无法从中得到真实地址。

^sniffer-content-script

### 配合 Playwright 加载扩展

将嗅探扩展内置到 Playwright 中的完整方案，详见 [[Playwright爬虫实战#^extension-manifest|Playwright 浏览器扩展集成]]。

## 二、手动查找真正的 M3U8 链接

不写代码，只用浏览器 F12 找出藏起来的 M3U8 链接的完整流程。

### 标准流程（三步走）

**第一步：准备工作**

1. 使用 Chrome 或 Edge 浏览器
2. 打开目标视频页面
3. 按 F12 打开开发者工具
4. 切换到 **Network（网络）** 面板
5. 点击清除按钮，清空已有记录

^manual-m3u8-step1

**第二步：直接过滤 m3u8**

1. 在过滤框（Filter）中输入 `m3u8`
2. 点击播放视频
3. 观察 Network 面板

**分辨真伪：**

- **假的/初级的 M3U8**：页面一加载就出现，内容简单，甚至指向 `.js` 文件
- **真的/次级的 M3U8**：播放后延迟 1-2 秒才出现，文件名可能随机，带有 `&sign=`、`&t=` 等签名和时间戳参数

**获取链接**：点击真 M3U8 请求 -> Headers 标签页 -> 复制 Request URL。

^manual-m3u8-step2

**第三步：如果过滤 m3u8 找不到**

1. 清除 Filter
2. 选择 **Fetch/XHR** 过滤器，只看 API 请求
3. 刷新页面并播放视频
4. 逐个排查 XHR 请求，查看 Response 标签页
5. 寻找类似这样的 JSON 数据：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "video_url": "https://..../index.m3u8?sign=xxxx&t=xxxx",
    "quality": "1080p"
  }
}
```

复制 `video_url` 的值，就是真正的 M3U8 链接。

^manual-m3u8-step3

### 终极手段：追踪 Initiator

如果连 XHR 里都找不到：

1. Filter 输入 `.ts`（视频片段文件）
2. 找到第一个 `.ts` 请求
3. 切换到 **Initiator（调用者）** 标签页
4. 查看调用栈，点击链接跳转到 **Sources** 面板中的对应代码行
5. 在该行设置断点（点击行号）
6. 刷新页面，在断点处查看变量值，找到包含完整 M3U8 链接的变量

### 流程精华版

```
F12 -> Network
  -> Filter: m3u8, 播放, 直接找
  -> 找不到: 清除Filter -> Fetch/XHR, 播放, 在Response里找
  -> 还找不到: Filter: .ts -> 第一个请求 -> Initiator -> 源码断点
```

## 三、浏览器兼容性问题处理

### 问题描述

Chromium Headless 被网站识别，提示"当前浏览器不支持 HTML5 播放"；Firefox 可以正常加载但无 PDF 功能。

### 解决思路

核心矛盾：需要能骗过网站的浏览器加载内容，又需要能生成 PDF 的浏览器保存内容。

**方案一**（详见 [[爬虫反爬与突破#^chromium-headless-new|反爬突破]]）：加强 Chromium 伪装
- 使用 `--headless=new` 参数
- 设置真实 User-Agent 和 Viewport
- 加载 Cookies

**方案二**（详见 [[爬虫反爬与突破#^persistent-context|反爬突破]]）：使用持久化浏览器配置
- 先手动登录
- Playwright 加载已配置好的浏览器数据目录

**方案三**（详见 [[爬虫反爬与突破#^firefox-chromium-trick|反爬突破]]）：Firefox + Chromium 联动
- Firefox 渲染页面 -> 提取 HTML -> Chromium 生成 PDF

## 四、Python 自动化视频下载

### 使用 Playwright 的完整流程

核心思路：利用 `page.on("request", ...)` 监听网络请求，自动捕获视频资源链接。

```python
from playwright.sync_api import sync_playwright
import subprocess
import time

m3u8_url_found = None

def download_video_with_ffmpeg(m3u8_url, save_path):
    """使用 ffmpeg 下载 m3u8 视频流"""
    try:
        print(f"成功捕获到 m3u8 链接: {m3u8_url}")
        command = [
            'ffmpeg',
            '-protocol_whitelist', 'file,http,https,tcp,tls,crypto',
            '-i', m3u8_url,
            '-c', 'copy',
            '-bsf:a', 'aac_adtstoasc',
            save_path
        ]
        subprocess.run(command, check=True)
        print(f"视频下载成功！已保存至: {save_path}")
    except FileNotFoundError:
        print("\n[错误] 未找到 ffmpeg 程序。")
    except subprocess.CalledProcessError as e:
        print(f"\n[错误] ffmpeg 下载失败。")

def main():
    start_url = "https://www.example.com"
    video_link_selector = 'a[data-href="/vod/details/29530"]'
    output_filename = "downloaded_video.mp4"

    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        context = browser.new_context(
            user_agent="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36"
        )
        page = context.new_page()

        def handle_request(request):
            global m3u8_url_found
            if ".m3u8" in request.url and not m3u8_url_found:
                print("成功拦截到 .m3u8 链接!")
                m3u8_url_found = request.url
                page.remove_listener("request", handle_request)

        try:
            page.on("request", handle_request)

            print(f"正在访问目录页面: {start_url}")
            page.goto(start_url, timeout=60000)

            print("正在查找目标视频链接...")
            video_link = page.locator(video_link_selector).first()
            video_link.click()

            print("正在后台监听网络，等待 .m3u8 链接出现...")
            for _ in range(30):
                if m3u8_url_found:
                    break
                time.sleep(1)

            if m3u8_url_found:
                download_video_with_ffmpeg(m3u8_url_found, output_filename)
            else:
                print("\n[错误] 等待 30 秒，仍未捕获到 .m3u8 链接。")

        except Exception as e:
            print(f"脚本运行出错: {e}")
        finally:
            browser.close()

if __name__ == "__main__":
    main()
```

^playwright-video-sniffing

### 使用 requests 流式下载

对于已知的视频 URL，使用 `stream=True` 分块下载，内存占用极低：

```python
import requests

def download_video(video_url, save_path):
    try:
        print(f"开始下载视频，URL: {video_url}")

        # stream=True：不一次性加载到内存，而是建立流式连接
        # timeout=30：30秒无响应则放弃
        response = requests.get(video_url, stream=True, timeout=30)
        response.raise_for_status()

        # 'wb'：二进制写入模式
        with open(save_path, 'wb') as f:
            # 每次搬运 8KB，像蚂蚁搬家一样逐块写入
            for chunk in response.iter_content(chunk_size=8192):
                if chunk:
                    f.write(chunk)

        print(f"视频下载完成，已保存至: {save_path}")

    except requests.exceptions.RequestException as e:
        print(f"下载视频时出错: {e}")
    except Exception as e:
        print(f"保存文件时出错: {e}")
```

^requests-stream-download

核心优势：
- **内存占用极低**：无论视频是 100MB 还是 10GB
- **稳健可靠**：有超时设置和错误检查
- **`stream=True`**：先建立连接，再逐块接收数据流

### 页面保存为 PDF 的完整自动化

```python
import asyncio
from playwright.async_api import async_playwright
import time

async def save_url_to_pdf(url: str, output_path: str):
    print(f"开始处理URL: {url}")
    start_time = time.time()

    async with async_playwright() as p:
        browser = await p.chromium.launch(headless=True)
        page = await browser.new_page()

        try:
            # wait_until='networkidle' 等待网络基本空闲
            print("正在访问页面并等待加载完成...")
            await page.goto(url, wait_until='networkidle', timeout=60000)

            # 可选：移除登录弹窗
            await page.evaluate('''() => {
                const loginModal = document.querySelector('.Modal-wrapper');
                if (loginModal) { loginModal.remove(); }
            }''')

            print("正在生成PDF文件...")
            await page.pdf(
                path=output_path,
                format='A4',
                print_background=True,
                margin={"top": "50px", "bottom": "50px"}
            )

        except Exception as e:
            print(f"处理过程中发生错误: {e}")
        finally:
            await browser.close()

    end_time = time.time()
    print(f"任务完成！PDF已保存至: {output_path}")
    print(f"总耗时: {end_time - start_time:.2f} 秒")

if __name__ == "__main__":
    asyncio.run(save_url_to_pdf(
        'https://zhuanlan.zhihu.com/p/587460935',
        'output.pdf'
    ))
```

^page-to-pdf

### Playwright vs Selenium 对比

| 特性 | Playwright（推荐） | Selenium |
|------|-------------------|----------|
| JS 支持 | 极好，专为此设计 | 好，但有时需手动等待 |
| 安装设置 | `playwright install` 自动搞定 | 需手动下载 WebDriver |
| 生成 PDF | `page.pdf()` 内置 | 需执行特殊打印命令 |
| 性能 | 通常更快 | 相对较慢 |

- **Python 端**：使用 `launch_persistent_context` 加载扩展，从 `chrome.storage.local` 读取捕获的链接
