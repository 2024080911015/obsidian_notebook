## 一、403 错误处理：自定义下载请求 Headers

当图片下载出现大量 403 时，根本原因是网站的防盗链机制。需要**继承 ImagesPipeline 并重写 `get_media_requests()`**，为每个下载请求添加 Referer 等头部。

### 自定义 Pipeline

```python
# my_pipelines.py
import scrapy
from scrapy.pipelines.images import ImagesPipeline
from scrapy.exceptions import DropItem

class CustomImagesPipeline(ImagesPipeline):

    def get_media_requests(self, item, info):
        """核心方法：为每个图片URL创建带自定义headers的下载请求"""
        urls = item.get(self.images_urls_field, [])

        for image_url in urls:
            try:
                request = scrapy.Request(
                    image_url,
                    headers={
                        'Referer': 'https://www.zhihu.com/',  # 伪造Referer，解决防盗链
                        'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...'
                    }
                )
                yield request
            except Exception as e:
                info.spider.logger.warning(
                    f"Failed to create request for {image_url}: {e}"
                )

    def item_completed(self, results, item, info):
        image_paths = [x['path'] for ok, x in results if ok]
        if not image_paths:
            raise DropItem("Item contains no images")
        item[self.images_result_field] = results
        return item
```

^custom-pipeline-403

### 启用自定义 Pipeline

```python
# settings.py
IMAGES_STORE = 'downloaded_images'

ITEM_PIPELINES = {
   # 'scrapy.pipelines.images.ImagesPipeline': 1,  # 注释掉官方
   'your_project.my_pipelines.CustomImagesPipeline': 1,  # 使用自定义
}
```

这个方法不仅可以添加 Referer，还可以：
- 为不同图片 URL 添加不同 Referer
- 给请求添加代理（`meta={'proxy': 'http://...'}`）
- 传递自定义 Cookie
- 实现更复杂的下载逻辑

## 二、缩略图到原图：四种侦查策略

几乎所有现代图片网站都不会把原图放在 `<img src>` 中。核心思路是把自己当成 "侦探"，通过 F12 开发者工具找出高清原图链接。

### 策略 1：链接标签的 href 属性

最常见也最友好的模式。缩略图被 `<a>` 包裹，原图在 `href` 中。

```html
<a href="https://example.com/path/to/high_quality_image.jpg">
    <img src="https://example.com/path/to/thumbnail.jpg">
</a>
```

^thumbnail-strategy1

**爬取方法**：提取 `<a>` 的 `href` 而非 `<img>` 的 `src`：

```python
response.css('div.image-container a::attr(href)').get()
```

### 策略 2：data-* 属性

原图链接藏在自定义属性中：

```html
<img class="lazyload"
     src="placeholder.gif"
     data-src="https://example.com/path/to/high_quality_image.jpg">
```

**爬取方法**：

```python
response.css('img.lazyload::attr(data-src)').get()
```

常见属性名：`data-src`, `data-original`, `data-high-res`, `data-url`

^thumbnail-strategy2

### 策略 3：JSON 数据包

网站将图片信息打包成 JSON 字符串存放在某个属性中（如必应图片的 `m` 属性）：

```html
<a class="iusc" m='{"murl":"https://example.com/high_quality_image.jpg", "turl":"...", ...}'>
    ...
</a>
```

**爬取方法**：

```python
import json

m_str = response.css('a.iusc::attr(m)').get()
data = json.loads(m_str)
original_url = data['murl']
```

^thumbnail-strategy3

### 策略 4：网络侦查找 API

如果以上方法都找不到，原图链接是通过后台 API 动态获取的：

1. F12 -> Network -> Fetch/XHR
2. 点击缩略图，观察新出现的 API 请求
3. 查看 Response 中的 JSON 数据，找到原图 URL

**爬取方法**：
- **方法 A（推荐）**：直接模拟该 API 请求，效率最高
- **方法 B（备用）**：使用 Playwright 模拟点击操作，从弹出的大图预览中提取 `src`

### 四种策略总结

| 策略 | 侦查方法（F12） | 爬取方法 |
|------|----------------|---------|
| 链接标签 | 检查 `<img>` 父标签 `<a>` 的 `href` | 直接提取 `href` 属性 |
| data-* 属性 | 检查 `data-src` 等属性 | 直接提取 `data-*` 属性 |
| JSON 数据包 | 检查属性中 `{...}` 格式字符串 | 提取字符串 -> `json.loads()` -> 取目标值 |
| API 请求 | 打开 Fetch/XHR，观察请求响应 | 模拟 API 请求 或 Playwright 模拟点击 |

## 三、DevTools 检测与绕过

### 现象

打开 F12 开发者工具后视频无法加载，关闭则正常。这说明网站的 JavaScript 能检测到 DevTools 的打开状态。

### 解决方法一：Playwright 自动化捕获（强烈推荐）

既然手动打开会被检测，就完全放弃手动操作，用 Playwright 在后台自动化运行：

```python
from playwright.sync_api import sync_playwright
import subprocess
import time

m3u8_url_found = None

def main():
    with sync_playwright() as p:
        # headless=True 在后台运行，更不容易被检测
        browser = p.chromium.launch(headless=True)
        context = browser.new_context(
            user_agent="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36"
        )
        page = context.new_page()

        def handle_request(request):
            global m3u8_url_found
            if ".m3u8" in request.url and not m3u8_url_found:
                print(f"成功拦截到 .m3u8 链接!")
                m3u8_url_found = request.url
                page.remove_listener("request", handle_request)

        try:
            # 导航前设置监听器
            page.on("request", handle_request)

            page.goto("https://target-site.com", timeout=60000)
            video_link = page.locator('a[data-href="/vod/details/29530"]').first()
            video_link.click()

            # 等待最多 30 秒
            for _ in range(30):
                if m3u8_url_found:
                    break
                time.sleep(1)

            if m3u8_url_found:
                # 调用 ffmpeg 下载
                subprocess.run([
                    'ffmpeg',
                    '-protocol_whitelist', 'file,http,https,tcp,tls,crypto',
                    '-i', m3u8_url_found,
                    '-c', 'copy',
                    '-bsf:a', 'aac_adtstoasc',
                    'downloaded_video.mp4'
                ])
        finally:
            browser.close()

if __name__ == "__main__":
    main()
```

^devtools-bypass-script

### 解决方法二：手动绕过技巧

- 将开发者工具**分离为独立窗口**（点击 DevTools 右上角三个点 -> Dock side -> 第一个图标 "分离到独立窗口"）
- 在分离模式下刷新页面，有时可绕过基于窗口尺寸的检测

## 四、浏览器指纹伪装强化

当 Chromium Headless 被检测为"不支持 HTML5 播放"时，需要加强伪装：

### 方案一：新版 Headless + stealth

```python
from playwright.async_api import async_playwright
from playwright_stealth import stealth_async

browser = await p.chromium.launch(
    headless=True,
    args=['--headless=new']  # 新版 headless 模式
)

context = await browser.new_context(
    user_agent="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36",
    viewport={"width": 1920, "height": 1080},
    storage_state="cookies_bilibili.json"
)

page = await context.new_page()
await stealth_async(page)
```

^chromium-headless-new

### 方案二：持久化浏览器配置

先手动配置好浏览器并登录，再让 Playwright 接管：

```python
USER_DATA_DIR = "D:/my_browser_data"

context = await p.chromium.launch_persistent_context(
    USER_DATA_DIR,
    headless=True,
    args=['--headless=new'],
    user_agent="Mozilla/5.0 ...",
    viewport={"width": 1920, "height": 1080},
)

page = context.pages[0] if context.pages else await context.new_page()
await stealth_async(page)
```

^persistent-context

### 方案三：Firefox + Chromium 联动（终极方案）

当 Chromium 被拦截但 Firefox 可以正常加载时：

1. 用 **Firefox** 加载页面，等待所有内容渲染完毕
2. 从 Firefox 提取完整的 HTML 内容
3. 启动**无头 Chromium**
4. 将 HTML "喂"给 Chromium，由 Chromium 生成 PDF

```python
async def vedio_trick(url: str, output_path: str):
    final_html = ""
    async with async_playwright() as p:
        # 步骤 1 & 2：Firefox 获取渲染好的 HTML
        print("步骤1：使用Firefox加载页面...")
        browser_ff = await p.firefox.launch(headless=True)
        page_ff = await browser_ff.new_page()
        await page_ff.goto(url, wait_until="networkidle")
        await page_ff.wait_for_timeout(5000)
        print("页面已在Firefox中加载，正在提取HTML...")
        final_html = await page_ff.content()
        await browser_ff.close()

        # 步骤 3 & 4：Chromium 加载 HTML 并生成 PDF
        print("步骤2：使用无头Chromium生成PDF...")
        browser_cr = await p.chromium.launch(headless=True)
        page_cr = await browser_cr.new_page()
        await page_cr.set_content(final_html, wait_until="networkidle")
        await page_cr.pdf(path=output_path, format="A4")
        await browser_cr.close()

        print(f"任务完成！PDF已保存到 {output_path}")
```

^firefox-chromium-trick

## 五、文件删除

### 通过 qBittorrent Web UI 删除（推荐）

1. 打开 `http://your_server_ip:8080` 并登录
2. 选中已完成的任务，右键 -> 删除
3. 务必勾选 "同时删除文件 (Also delete files on disk)"

### 通过 SSH 命令行删除

```bash
# 导航到下载目录
cd /home/qbuser/Downloads

# 确认目标文件存在
ls -l

# 删除单个文件
rm "文件名"

# 删除整个文件夹
rm -rf "文件夹名"
```

^safe-delete

**安全警告**：`rm -rf` 不可恢复，执行前请再三确认路径和文件名。使用 `pwd` 确认当前目录。
