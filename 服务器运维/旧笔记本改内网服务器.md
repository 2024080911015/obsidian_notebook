# 旧笔记本改内网服务器

## 一、概述

将旧笔记本电脑改造为内网服务器，并通过内网穿透技术实现公网访问。适用于家中有闲置设备、想搭建 NAS/下载器/Web 服务/开发环境等场景。

核心目标：从公网任意位置 SSH 连接到位于内网（没有公网 IP）的笔记本服务器。

## 二、SSH 反向隧道方案

利用香港（或其他有公网 IP 的）服务器作为中转，通过 SSH 反向隧道实现内网穿透。^reverse-tunnel

### 核心原理

连接不是从公网到内网（会被 NAT/防火墙阻止），而是由**内网服务器主动发起并维持**一条到公网服务器的隧道。公网服务器监听一个端口，该端口收到的所有数据通过已建立的隧道转发到内网服务器。

```
你在任何地方 (公网)
       |
       |  1. SSH 请求
       v
香港公网服务器 (监听指定端口，例如 2222)
       |
       |  2. 通过已建立的隧道转发
       v
[SSH 反向隧道]
       |
       |  3. 请求到达内网服务器
       v
你的内网笔记本服务器 (SSH 服务在 22 端口)
```

### 约定

- **香港服务器（公网）**：IP 为 `PUBLIC_IP`，用户名为 `user_public`
- **笔记本服务器（内网）**：用户名为 `user_private`

### 第一步：配置香港公网服务器

```bash
# 登录公网服务器
ssh user_public@PUBLIC_IP

# 编辑 SSHD 配置
sudo nano /etc/ssh/sshd_config
```

找到 `GatewayPorts` 行，修改为：

```ini
GatewayPorts yes
```

> 这个设置允许 SSH 将远程端口转发绑定到 `0.0.0.0`，使公网上的其他机器可以访问转发端口。默认 `no` 只会绑定到 `localhost`。

重启 SSH 服务：

```bash
sudo systemctl restart sshd
```

### 第二步：在内网笔记本上建立反向隧道

在内网笔记本终端执行：

```bash
ssh -fN -R 2222:localhost:22 user_public@PUBLIC_IP
```

参数详解： ^reverse-tunnel-params
- `-f`：连接成功后转入后台运行
- `-N`：不执行远程命令，仅做端口转发
- `-R 2222:localhost:22`：反向隧道，将公网服务器的 `2222` 端口收到的流量转发到内网机器的 `22` 端口
- `2222`：公网服务器监听端口（从 1024 以上选一个未被占用的）

### 第三步：从公网连接内网服务器

在任何地方的终端执行：

```bash
ssh user_private@PUBLIC_IP -p 2222
```

- `user_private`：内网笔记本的用户名
- `PUBLIC_IP`：香港公网服务器的 IP
- `-p 2222`：指定端口

输入内网笔记本的密码即可登录。

## 三、autossh 持久化隧道

普通 `ssh -R` 的缺点是网络中断或连接超时后隧道断开，需手动重连。`autossh` 可以守护这个连接。

### 安装 autossh

```bash
# Debian/Ubuntu
sudo apt update
sudo apt install autossh

# CentOS/RHEL
sudo yum install autossh
```

### 配置 SSH 密钥对（免密登录）

在内网笔记本上：

```bash
# 生成密钥（如果还没有）
ssh-keygen -t rsa
# 一路回车

# 将公钥复制到香港服务器
ssh-copy-id user_public@PUBLIC_IP
# 输入一次密码后不需要再输入
```

### 使用 autossh 建立隧道

```bash
autossh -M 20000 -fN -R 2222:localhost:22 user_public@PUBLIC_IP
```

- `-M 20000`：autossh 使用端口 20000 和 20001 监控连接状态，断线自动重连

### 优化的 autossh 命令

```bash
autossh -M 0 -o "ServerAliveInterval=30" -o "ServerAliveCountMax=3" -N -R 2222:localhost:22 root@公网IP
```

参数说明：
- `-M 0`：关闭 autossh 自己的监控端口，完全依赖 SSH 内置的心跳检测
- `ServerAliveInterval=30`：每 30 秒发送心跳包
- `ServerAliveCountMax=3`：连续 3 次心跳失败后断开重连
- 这种方式更简洁，不占用额外端口

### 设置开机自启（终极方案）

在内网笔记本上创建 systemd 服务：

```bash
sudo nano /etc/systemd/system/autossh-tunnel.service
```

```ini
[Unit]
Description=AutoSSH tunnel to public server
After=network.target

[Service]
User=user_private
Group=user_private
# systemd 管理后台进程，所以不加 -f 参数
ExecStart=/usr/bin/autossh -M 20000 -N -R 2222:localhost:22 user_public@PUBLIC_IP
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable autossh-tunnel.service
sudo systemctl start autossh-tunnel.service
sudo systemctl status autossh-tunnel.service
```

> `User` 和 `Group` 应设为内网笔记本上运行此命令的普通用户名。

^autossh-service

## 四、内网穿透其他方案

### 方案一：ngrok（最简单，5分钟搞定）

适合临时演示、开发调试。

```bash
# 注册 ngrok 账号后
ngrok config add-authtoken [你的AuthToken]

# 穿透本地 80 端口
ngrok http 80

# 穿透本地 3000 端口
ngrok http 3000
```

执行后终端会显示一个公网地址（如 `https://random-string.ngrok-free.app`），发给任何人都能访问你的本地服务。

- **优点**：极简，无需服务器
- **缺点**：免费版域名随机、带宽有限、每次断开后重新连接域名会变

### 方案二：frp（功能最强，完全可控）

适合长期、稳定、多服务穿透。需要一台有公网 IP 的 VPS。^frp-setup

#### 服务端（VPS）配置

```bash
# 下载 frp
wget https://github.com/fatedier/frp/releases/download/v0.58.1/frp_0.58.1_linux_amd64.tar.gz
tar -zxvf frp_0.58.1_linux_amd64.tar.gz
cd frp_0.58.1_linux_amd64

# 编辑 frps.ini（或 frps.toml）
nano frps.ini
```

```ini
[common]
bind_port = 7000
```

启动服务端：

```bash
nohup ./frps -c ./frps.ini &
```

> 别忘了在 VPS 安全组中放行 7000 端口。

#### 客户端（内网设备）配置

编辑 `frpc.ini`：

```ini
[common]
server_addr = 你的VPS公网IP
server_port = 7000

[web_server_1]
type = http
local_ip = 127.0.0.1
local_port = 80
custom_domains = www.你的域名.com

[ssh_access]
type = tcp
local_ip = 127.0.0.1
local_port = 22
remote_port = 6000
```

启动客户端：

```bash
./frpc -c ./frpc.ini
```

之后可以通过 `ssh -p 6000 user@你的VPS公网IP` 连接内网设备。

### 方案三：ZeroTier（虚拟局域网）

适合多台设备安全互访，不暴露任何端口到公网。^zerotier

1. 在 [my.zerotier.com](https://my.zerotier.com) 注册并创建网络（获得 16 位网络 ID）
2. 在所有设备上安装 ZeroTier 客户端
3. 在客户端中 "Join New Network"，输入网络 ID
4. 在管理页面授权加入的设备
5. 授权后每台设备获得虚拟内网 IP（如 `10.147.17.21`）
6. 直接使用虚拟 IP 访问设备：

```bash
ssh user@10.147.17.21
# 或在文件管理器中输入 \\10.147.17.22 访问 Windows 共享文件夹
```

### 方案四：Cloudflare Tunnel（不需要公网 IP）

详见 [[计算机网络知识/内网穿透]]。Cloudflare Tunnel 通过 `cloudflared` 在内网设备上创建到 Cloudflare 的隧道，利用 Cloudflare 的全球网络提供公网访问。

### 方案对比

| 方案 | 需要公网 IP | 难度 | 适用场景 |
|------|-----------|------|---------|
| SSH 反向隧道 | 需要（VPS） | 中等 | 个人长期穿透 |
| autossh + systemd | 需要（VPS） | 中等 | 稳定持久化穿透 |
| ngrok | 不需要 | 极简 | 临时演示、开发调试 |
| frp | 需要（VPS） | 中等 | 多服务、高带宽穿透 |
| ZeroTier | 不需要 | 简单 | 多设备安全互访 |
| Cloudflare Tunnel | 不需要 | 中等 | Web 服务穿透 |

^penetration-compare

## 五、外接硬盘配置

旧笔记本改造服务器后，常需要外接硬盘扩展存储。

### 查看磁盘

```bash
lsblk -f
```

输出示例：
```
sdb                    # 外接硬盘
├─sdb1
└─sdb5  ntfs  赵丛垒E899306CA8172634  # NTFS 分区，未挂载
```

### 挂载 NTFS 分区

```bash
# 安装 NTFS 支持
sudo apt update && sudo apt install ntfs-3g

# 创建挂载点
sudo mkdir -p /mnt/usb_disk

# 挂载
sudo mount -t ntfs-3g /dev/sdb5 /mnt/usb_disk

# 修改权限
sudo chown -R username:username /mnt/usb_disk
```

之后可以通过 WinSCP 等工具访问 `/mnt/usb_disk` 路径查看文件。

### 设置开机自动挂载

编辑 `/etc/fstab`，添加：

```ini
/dev/sdb5 /mnt/usb_disk ntfs-3g defaults 0 0
```

或使用 UUID（推荐，更稳定）：

```bash
# 先查看 UUID
blkid /dev/sdb5

# 然后在 /etc/fstab 中使用：
UUID=你的UUID /mnt/usb_disk ntfs-3g defaults 0 0
```

^external-disk

## 六、安全建议

1. **防火墙**：在香港公网服务器上只开放必要端口（22、2222 等）
2. **SSH 密钥**：两台服务器都禁用密码登录，仅使用 SSH 密钥
3. **选择端口**：不要使用过于常见的端口作为隧道监听端口
4. **定期更新**：保持两台服务器的系统安全更新
