# 域名配置

## 一、概述

将域名绑定到服务器上的 Web 应用，实现通过域名访问服务。整体架构为：

```
用户访问 design.example.com
        ↓
DNS 解析 → 服务器 Nginx 监听 80/443
        ↓
反向代理 → Flask / Node.js / 其他后端应用
```

## 二、DNS 解析配置

### 确认服务器公网 IP

```bash
# 在服务器上执行
curl ifconfig.me
# 假设返回：1.2.3.4
```

### 添加 DNS 记录

去域名购买商后台（阿里云、腾讯云、Cloudflare、Namecheap 等），添加 A 记录：

| 类型 | 主机记录 | 记录值 |
|------|---------|--------|
| A | design | 1.2.3.4 |

> 主机记录 `design` 意味着域名 `design.example.com` 指向 `1.2.3.4`。
> 如果要让主域名 `example.com` 也指向服务器，主机记录填 `@`。

### 验证 DNS 生效

```bash
ping design.example.com
```

如果能解析到服务器 IP，说明 DNS 配置成功。生效时间从几分钟到几十分钟不等。

^dns-config

## 三、应用后端配置

### Flask 应用示例

将 Flask 应用配置为只监听本地端口（不直接暴露到公网）：

```python
# app.py
if __name__ == "__main__":
    app.run(host="127.0.0.1", port=5000)
```

> 使用 `127.0.0.1` 是因为 Nginx 负责对外，Flask 与 Nginx 在服务器内部通信即可，无需对外开放 5000 端口。

### 配置 systemd 服务（后台运行）

创建服务文件：

```bash
sudo nano /etc/systemd/system/class_design.service
```

```ini
[Unit]
Description=Class Design Flask Application
After=network.target

[Service]
User=root
WorkingDirectory=/root/class_design
ExecStart=/usr/bin/python3 /root/class_design/app.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl start class_design
sudo systemctl enable class_design
sudo systemctl status class_design
```

验证 Flask 是否运行：

```bash
curl http://127.0.0.1:5000
```

^flask-systemd

## 四、Nginx 反向代理

### 安装 Nginx

```bash
sudo apt update
sudo apt install nginx -y
sudo systemctl start nginx
sudo systemctl enable nginx
sudo systemctl status nginx
```

### 配置站点

创建 Nginx 配置文件：

```bash
sudo nano /etc/nginx/sites-available/design.example.com
```

```nginx
server {
    listen 80;
    server_name design.example.com;

    # 上传文件大小限制
    client_max_body_size 100M;

    location / {
        # 反向代理到 Flask 应用
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

配置说明： ^nginx-proxy-config
- `server_name`：指定该配置块对应哪个域名
- `proxy_pass`：将请求转发到后端应用
- `proxy_set_header`：转发原始请求的真实信息（客户端 IP、协议等）

### 启用站点

```bash
sudo ln -s /etc/nginx/sites-available/design.example.com /etc/nginx/sites-enabled/
```

### 验证配置并重启

```bash
# 检查语法
sudo nginx -t
# 应显示：syntax is ok / test is successful

# 重启 Nginx
sudo systemctl restart nginx
```

### 测试访问

```bash
curl http://design.example.com
```

或直接在浏览器打开 `http://design.example.com`。

^nginx-setup

## 五、HTTPS 配置（Let's Encrypt 免费证书）

### 安装 Certbot

```bash
sudo apt install certbot python3-certbot-nginx -y
```

### 申请证书

```bash
sudo certbot --nginx -d design.example.com
```

按照提示操作：
1. 输入邮箱地址
2. 同意服务条款
3. 选择是否自动跳转 HTTPS（建议选"是"）

完成后访问：`https://design.example.com`

### 证书自动续期

Let's Encrypt 证书有效期为 90 天，Certbot 会自动配置定时任务进行续期。手动测试续期：

```bash
sudo certbot renew --dry-run
```

## 六、防火墙与安全组

如果服务器安全组/防火墙有限制，需要放行 HTTP 和 HTTPS 端口：

```bash
# ufw
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# firewalld
sudo firewall-cmd --zone=public --add-port=80/tcp --permanent
sudo firewall-cmd --zone=public --add-port=443/tcp --permanent
sudo firewall-cmd --reload
```

> **注意**：Flask 的 5000 端口**不需要**对外开放，因为 Nginx 和 Flask 在同一台服务器内部通过 `127.0.0.1:5000` 通信。

## 七、完整架构总结

```text
/root/class_design/app.py
        ↓
systemd 后台运行 Flask，监听 127.0.0.1:5000
        ↓
Nginx 监听 80/443 端口
        ↓
design.example.com（HTTPS）
```

最终推荐结构：

- 应用只监听本地回环地址（`127.0.0.1`），不直接暴露公网
- Nginx 作为反向代理处理所有外部请求
- Let's Encrypt 提供免费 HTTPS 证书
- 日志通过 systemd 的 `journalctl` 查看

## 八、常用管理命令

```bash
# 重启 Flask 应用
sudo systemctl restart class_design

# 查看 Flask 实时日志
sudo journalctl -u class_design -f

# 重启 Nginx
sudo systemctl restart nginx

# 检查 Nginx 配置语法
sudo nginx -t

# 查看 Nginx 状态
sudo systemctl status nginx
```

## 九、故障排查流程

如果打不开域名，按顺序检查：

```bash
# 1. 确认 Flask 应用运行
sudo systemctl status class_design

# 2. 确认 Nginx 运行
sudo systemctl status nginx

# 3. 确认 Flask 本地可访问
curl http://127.0.0.1:5000

# 4. 确认 Nginx 代理可访问
curl http://design.example.com

# 5. 确认 DNS 解析
ping design.example.com
```
