# 浏览器开发者工具

## 一、概述

浏览器开发者工具（DevTools）是浏览器内置的网页调试工具集，用于查看网页结构、分析网络请求、调试 JavaScript、修改样式等。默认以 Chrome / Edge（Chromium 内核）为例讲解。

> 相关阅读：[[浏览器扩展开发]] 利用 DevTools 调试扩展；[[爬虫与自动化/爬虫反爬与突破]] 利用 Network 面板分析接口。

---

## 二、打开方式

| 方法 | 快捷键/操作 |
|------|------------|
| 最常用 | `F12` |
| 快捷键 | `Ctrl + Shift + I` (Win) / `Cmd + Option + I` (Mac) |
| 鼠标 | 页面右键 -> "检查 / Inspect" |

> Mac 用户注意：如果 F12 没反应，请用 `Fn + F12`。

---

## 三、面板概览

DevTools 打开后，顶部有一排标签（Tab），最重要的三个是：

| 标签 | 用途 | 新手优先级 |
|------|------|------------|
| Elements | 看/改 HTML + CSS | 最高 |
| Console | 看报错、写 JS | 最高 |
| Network | 看接口、请求、数据 | 最高 |
| Sources | JS 源码调试 | 中 |
| Application | 本地存储 / Cookie | 中 |
| Performance | 性能分析 | 低 |
| Security | 证书、TLS 信息 | 低 |

> 90% 的日常使用，只靠 **Elements + Console + Network** 三个面板。

## 四、Elements 面板（看网页结构 + 改样式）

### 4.1 用箭头选中元素

1. 点击 DevTools 左上角的"小箭头图标"（元素选择器）
2. 再用鼠标点网页上的任意内容
3. 左侧 HTML 自动定位到对应标签，右侧显示 CSS 样式

这是理解网页结构的入口。

### 4.2 看 HTML 三要素

```
<div class="title" id="main">Hello</div>
```

- **标签名**：`div`、`span`、`a`、`img` 等
- **class**：`class="title"` —— CSS 类名
- **id**：`id="main"` —— 唯一标识

前端定位、爬虫、改样式，全靠这三种选择器。

### 4.3 改样式（Styles 面板）

在右侧 Styles 面板最顶部找到 `element.style {}`，直接在 `{}` 里写 CSS：

```css
color: red;
font-size: 28px;
background: yellow;
```

- 颜色值可以用 `red`、`#ff6600`、`rgb(0,128,255)`、`purple` 等
- 如果写了颜色但没生效（出现删除线），加 `!important`：

```css
color: red !important;
```

- `element.style` 是手动写入的样式，优先级最高，最不容易被覆盖

> **重要**：这些修改只是本地看到的，一刷新页面就没了，不会影响真实网站。

### 4.4 修改文字内容

**方法 1：双击改字（最快）**

在 Elements 面板选中包含文字的元素，直接在文字上双击 -> 修改 -> 回车。

**方法 2：Edit as HTML（更稳）**

右键当前元素 -> 选 "Edit as HTML" -> 修改 -> 点击空白处生效。

**方法 3：Console 改文本（进阶）**

```javascript
// $0 = 当前在 Elements 里选中的那个元素
$0.textContent = "这是我改过的内容";

// 保留 HTML 标签
$0.innerHTML = "这是 <b>加粗</b> 后的新内容";

// 按条件批量改
document.querySelectorAll("p").forEach(p => {
  p.textContent = "统一替换的文字";
});
```

## 五、Console 面板（JS 交互 + 排错）

### 5.1 Console 是什么

- 浏览器的"命令行"
- JavaScript 交互窗口
- 报错集中地

打开方式：点 Console 标签，或快捷键 `Ctrl + Shift + J`。

### 5.2 基础命令

```javascript
1 + 1                    // 计算
document.title           // 读取网页标题
alert("Hello")           // 弹窗
```

### 5.3 看报错

Console 里的**红字 = 网页错误**。

常见用途：
- 网页打不开？看 Console
- 插件失效？看 Console
- 前端报错？看 Console

程序员第一反应：先看 Console。

### 5.4 查看公网 IP

> **重要前提**：Console 不是"万能 JS 环境"。同一段 JS，在不同文档上下文里权限完全不同。

| 页面类型 | 是否有 CSP | 能否 fetch 外网 |
|----------|-----------|----------------|
| `about:blank` | 没有 | 可以 |
| 普通 http(s) 网页 | 视网站而定 | 可能 |
| chatgpt.com | 有（严格） | 不行 |
| `chrome://` / 新标签页 | 有（极严格） | 不行 |

**正确做法（在 `about:blank` 中执行）**：

1. 新开标签页
2. 地址栏输入 `about:blank`
3. 回车后再按 F12 打开 DevTools
4. Console 输入：

```javascript
fetch("https://api.ipify.org?format=json")
  .then(r => r.json())
  .then(console.log)
```

即可看到：`{ ip: "你的公网IP" }`

**判断口诀**：
- 想随便 fetch 外网 -> 用 `about:blank`
- 想看某网站真实行为 -> 在那个网站里 Network 看
- `chrome://` / 新标签页 不等于 普通网页

## 六、Network 面板（抓接口 / 看数据）

这是最有价值、最强的一个面板。

### 6.1 正确打开姿势

1. 打开 Network 标签
2. 勾选 **Preserve log**（保留日志，避免跳转后丢请求）
3. 勾选 **Disable cache**（禁用缓存）
4. 点 **Clear**（清空列表）
5. 刷新页面（F5）

否则你会看到 Network 面板是空的。

### 6.2 看哪些请求

**筛选按钮**：

| 类型 | 作用 |
|------|------|
| Fetch/XHR | 接口数据（JSON）-- 最重要 |
| Doc | 页面本身（HTML 文档） |
| JS | JavaScript 文件 |
| CSS | 样式表 |
| Img/Media | 图片、视频资源 |

> 爬虫抓数据 -> 只点 **Fetch/XHR**

### 6.3 点开一个请求看什么

一个请求点开后，看这几个 Tab：

| Tab | 内容 |
|-----|------|
| Headers | 请求地址、方法、参数 |
| Payload / Request | 你传给服务器的数据 |
| Response | 服务器返回的数据（最重要） |
| Timing | 请求各个阶段的耗时 |

如果你看到 Response 里有 JSON：

```json
{
  "code": 0,
  "data": { ... }
}
```

恭喜，你已经找到了"接口"。

### 6.4 显示更多列

在 Network 请求列表的表头（Name/Status/Type/Initiator/Size/Time）上**右键**，勾选：

- **Protocol**：显示 h2/h3 等信息
- **Remote Address**：显示连接的远端 IP
- **Error**：显示错误原因

### 6.5 导出 HAR 文件

在 Network 列表空白处右键 -> **Save all as HAR with content**

HAR 文件完整记录：每个请求的时间、阶段、错误、头信息，适合做报告/复盘。

## 七、查看是否使用代理

### 7.1 看 Remote Address

Network -> 选中请求 -> Headers -> General -> **Remote Address**

你会看到类似：

```
104.xxx.xxx.xxx:443
172.xxx.xxx.xxx:443
```

**判断方法**：

- 如果 Remote Address 是目标网站的常见 IP 段：没走代理
- 如果 Remote Address 是阿里云/腾讯云/Vultr/AWS 等云服务商地址，而目标网站不在这些服务商：**高概率走了代理/VPN/隧道**

### 7.2 结合 Timing 判断

正常网站的 Timing 会完整覆盖 DNS、TCP、TLS、HTTP 和下载阶段。通过代理时，TCP 连接可能更快（走内网），但 Remote Address 会暴露真实的终点 IP。

## 八、网络连接诊断（Timing 面板）

### 8.1 正常联网过程

正常访问一个 HTTPS 网站时，Timing 会完整走完：

```
Queueing -> DNS Lookup -> Initial connection -> SSL -> Request sent -> Waiting (TTFB) -> Content Download
```

| 阶段 | 说明 | 正常耗时 |
|------|------|----------|
| Queueing | 浏览器排队等待连接 | 微秒~几毫秒 |
| DNS Lookup | 域名解析为 IP | 1~50 ms |
| Initial connection | TCP 三次握手 | 10~100 ms |
| SSL/TLS | 加密握手 + 校验证书 | 20~200 ms |
| Request sent | 发送 HTTP 请求 | 接近于 0 |
| Waiting (TTFB) | 等待服务器第一个响应字节 | 几十~几百 ms |
| Content Download | 下载内容 | Size > 0 B |

正常网站（如 Bing）做对照实验：
- 每一段都有时间
- 没有"已停止"
- 没有长时间空白

### 8.2 连接失败的四种情况

**情况 A：卡在 DNS Lookup**

- 页面报 `ERR_NAME_NOT_RESOLVED`
- Timing 里 DNS 很久或失败
- 结论：DNS 层面无法正确解析或被干预

**情况 B：卡在 Initial connection**

- DNS 很快结束
- Timing 卡在 Initial connection 很久
- 页面常报 `ERR_CONNECTION_TIMED_OUT`
- 结论：TCP 建连失败（丢包/阻断/路由不可达）

**情况 C：卡在 SSL**

- DNS OK、TCP 可能成功
- Timing 卡在 SSL
- 可能报 `ERR_CONNECTION_RESET` / `ERR_SSL_PROTOCOL_ERROR`
- 结论：TLS 握手阶段失败

**情况 D：卡在 Waiting (TTFB)**

- DNS/TCP/TLS 都过了
- Waiting (TTFB) 很久
- 结论：HTTP 层被阻断/重置

### 8.3 Google 连接测试对照表

以在中国大陆访问 Google 为例：

| 阶段 | 正常网站（如 Bing） | Google |
|------|-------------------|--------|
| DNS | 很快完成 | 完成 |
| TCP 连接 | 很快完成 | 卡住/中断 |
| TLS | 正常完成 | 未开始 |
| HTTP 请求 | 正常发送 | 未发送 |
| 下载内容 | Size > 0 | 0 B |
| Console | 有输出 | 空 |

## 九、实际练习

### 练习：找到一个接口并看到 JSON 数据

1. 打开任意资讯网站/电商网站
2. 按 F12 打开 DevTools
3. 切换到 Network 标签
4. 勾选 Preserve log + Disable cache
5. 刷新页面（F5）
6. 点击 Fetch/XHR 筛选
7. 点击某个请求
8. 查看 Response 标签

如果你能看到 JSON 格式的数据，就说明你已经掌握了 DevTools 的核心用法。

### 最小诊断实验（适用于网络连通性测试）

1. 打开无痕窗口（减少扩展干扰）
2. 打开 DevTools -> Network，勾选 Preserve log + Disable cache，点 Clear
3. 访问目标网站（如 `https://www.google.com/`）
4. 在 Network 列表中找 Type 为 `document` 的主请求
5. 点开 -> 看 Timing 截图
6. 把浏览器错误码（ERR_XXX）记下
7. 根据 Timing 判断卡在 DNS / TCP / TLS / HTTP 的哪一步
